# antislop audit 002: human / accessibility (2026-11-20)

Scope: full site (`src/`, `index.html`). This pass follows audit 001 and covers only the antislop-human concern: contrast, keyboard, focus, states, zoom, and the mobile keyboard.

Method:
- Code inspection.
- Every colour pairing computed with the WCAG 2.x formula. Opacity layers were blended first, and Tailwind `color-mix` values were mixed in oklab.
- The production build (`vite build` + `vite preview`) driven with headless Chrome over CDP:
  - real Tab key events;
  - clipped-content scans at 1280×800, 1366×768, 1280×720, 960×540 (200% zoom on 1080p), 640×400 (200% on 1280×800), and 320×256 (400% reflow);
  - opening a sheet.

Not exercised:
- Screen-reader speech.
- A physical mobile keyboard.
- Windows forced-colors rendering.

Priority: HIGH = blocks or hides content for a group of people. MEDIUM = degrades a task. LOW = polish or edge case.

---

## HIGH

**1. Signal Red fails as text and as the focus ring on light surfaces** (R-25, R-32, WCAG 1.4.3 / 1.4.11)

`#ff3656` measures 2.97:1 on `#e8ebf0` and 3.31:1 on `#f5f7fa`, so it fails both the 3:1 non-text bar and the large-text bar. DESIGN.md records this only for the stat numerals. The same red also does all of the following on the light ground:

- **Global focus ring** (`main.css:113`, 2.97:1). Keyboard users on the light theme get a ring below 3:1 on every page-background control.
- **Small text:**
  - active nav label (11–12px, `Navbar.vue:31`);
  - focused form labels (0.7rem, `Contact.vue:86/98/113`);
  - message counter past 800 (`Contact.vue:114`);
  - marquee role names (0.75rem, `About.vue:308`);
  - mobile divider numbers (`main.css:400`);
  - inline "4+ years" / "considered" in body copy (`About.vue:53`);
  - ghost-button hover text (2.55:1 on its tint, `main.css:171`).
- **Large text and icons:**
  - "Fully shipping." (`Home.vue:57`);
  - About stat numerals and "One… Hands.";
  - Contact "what's";
  - Features second title line;
  - the system-mode theme icon (`Navbar.vue:51`).

Fix: the plates keep `#ff3656` (ink on the red plate measures 4.99:1, which passes). Add one token for red used on light surfaces: `--color-light-primary-ink: #b7243b` (`color-mix(in oklab, #ff3656 78%, #000)`).

| Pairing | Ratio |
|---|---|
| on `#e8ebf0` | 5.28:1 |
| on card `#f5f7fa` | 5.88:1 |
| on ghost-hover tint | 4.54:1 |

Point the focus ring, the text uses listed above, and the ghost hover at the new token. Dark mode is untouched, because Filament Yellow on `#18181b` measures 11.58:1.

**2. Contact accent plate clips its own contact details at common laptop sizes** (R-35, WCAG 1.4.4 / 1.4.10, C-3)

`.contact-left` is `overflow-hidden` with a fixed slide height. Measured on the built site:

| Viewport | Clipped and unreachable |
|---|---|
| 1280×800 | social pills cut 5px |
| 1366×768 | LinkedIn / Facebook / Behance fully below the plate |
| 1280×720 | CV "Download PDF" + all socials |
| 960×540 (200% zoom on 1080p) | Email, Based, Status, CV, and all socials |

The clipped links stay in the tab order, so focus lands on controls nobody can see.

Fix:
- Give the plate `md:overflow-y-auto`, as the form half already has.
- Make the headline height-aware (`clamp(2.25rem, min(4.8vw, 8.5vh), 4.25rem)`).
- Let the vertical gaps use `vh`-bounded clamps so a 768px-tall screen fits without scrolling.

**3. Custom cursor disappears on the yellow plates in dark mode** (non-text contrast)

The native cursor is hidden (`cursor: none`). In dark mode the replacement dot and ring are `#e8ebf0`, which measures 1.28:1 on `#ffca26`. Over the left half of Home, About, Contact, and every Features illustration, mouse users lose the pointer. Light mode is fine (ink on red, 4.99:1).

Fix: in `CustomCursor.vue`, set an `on-accent` class when the hovered target sits inside `[data-accent-surface]`, and paint the dot and ring with `--color-dark` there.

**4. The navbar comes last in the tab order** (R-32)

`WebView.vue:119` renders `<navbar>` after `</main>`. Measured Tab sequence: skip link → Next arrow → Home content → socials → nav. The nav is visually first, but keyboard users reach it only after the whole panel, and the skip link skips nothing.

Fix: move `<navbar>` to directly after the skip link. It is `position: fixed`, so the visual layout does not change.

**5. Form field boundaries are invisible to low vision** (WCAG 1.4.11)

The fields are underline-only, at `border-current/25`:

| Theme | Ratio |
|---|---|
| light | 1.70:1 |
| dark | 2.10:1 |

The underline is the only edge that shows where to type.

Fix: `border-current/50`, which gives 3.22:1 light and 4.60:1 dark (`Contact.vue:88/100/117`).

## MEDIUM

**6. Send button drops keyboard focus while sending**

`:disabled="loading"` disables the focused button, and Chrome then moves focus to `<body>`. After a submit, keyboard and screen-reader users are back at the top of the document.

Fix: use `aria-disabled` plus an early return in `onSubmit`, and keep the button focusable.

**7. Success message may never be announced**

`role="status"` sits on an element mounted with `v-if`. A live region inserted with its text already inside is often skipped, especially by VoiceOver.

Fix: keep a permanent empty `role="status"` container and swap only its content.

**8. Mobile: the first invalid field can stay hidden after a failed submit** (R-03)

`focusFirstError` always passes `preventScroll: true`, which exists for the desktop pager. On the stacked mobile layout, Name sits above the Send button. Focus moves there and the keyboard opens, but the field is not scrolled into view.

Fix: keep `preventScroll` only at ≥768px. Below that, `scrollIntoView({ block: 'center' })`.

**9. Theme toggle edge is under 3:1 in light** (WCAG 1.4.11)

`border-black/40` measures 2.78:1, and this is an icon-only round control.

Fix: `border-black/50`. Its system icon is handled by #1.

**10. Mobile nav: visible label ≠ accessible name** (WCAG 2.5.3)

Below `sm`, each nav button shows only "01"–"05", but `aria-label` says "Home", "Features", and so on. A voice-control user who says "click 03" gets nothing.

Fix: drop `aria-label`, keep the visible number, and add the name as an `sr-only` span. The accessible name then reads "03 Works".

**11. Motion that never stops** (WCAG 2.2.2, Level A). Owner decision needed.

- The About marquee loops every 55s and pauses on mouse hover only.
- The Home typewriter cycles forever.
- The pulse dots loop.

`prefers-reduced-motion` stops all of them, but only for visitors who have set that preference. Options:

- **(a)** The typewriter types once and stays on the first title. The marquee gets a small pause/play control, and its pause also triggers on tap and focus.
- **(b)** Keep as is, and record the reliance on reduced-motion in DESIGN.md as a known gap.

## LOW

**12. Work-card focus ring is box-shadow only.**

`focus-visible:outline-none` plus a box-shadow ring (`Works.vue:42`). Windows High Contrast removes box-shadows, which leaves no indicator.

Fix: `focus-visible:outline-2 focus-visible:outline-transparent`. The transparent outline renders in forced colors and stays invisible otherwise.

**13. Mobile section-divider names use opacity 0.60.**

4.39:1 on light (`main.css:404`). Raise to 0.65, the documented floor.

**14. Icon glyphs leak into accessible names.**

Font Awesome is CSS-only, so `::before` private-use glyphs are added to the computed name of text buttons that lack `aria-hidden` on the `<i>`:
- "Visit Live" and "Close" (`Works.vue:140/144`);
- the case-study CTA and back arrow (`WorkDetails.vue:9/45`);
- the card type tag (`Works.vue:59`).

**15. The sheet has no close control of its own.**

While a case study loads (skeleton state), the only ways out are Esc or dragging the handle. Touch screen-reader users can't do either. Add a labelled close button to the sheet header.

**16. A filter change is silent.**

The "5 / 24 Projects" count updates without an announcement. Add `aria-live="polite"` to that line (`Works.vue:8`).

**17. Inactive filter-pill borders.**

| Theme | Ratio |
|---|---|
| light | 2.17:1 |
| dark | 2.91:1 |

The text label still identifies each control, so this is not a hard fail. Optional: `/50`.

**18. DESIGN.md "Known contrast gaps" is stale.**

- The teal/green case-study bullet was fixed in audit 001.
- The red bullet understates scope (see #1).

Update it after the fixes.

## Checked and clean

- The skip link is the first stop and lands on `<main>`.
- Off-screen desktop panels are `inert`.
- Hidden pager arrows are `disabled` and out of the tab order.
- Dialogs:
  - focus moves to the root;
  - Tab is trapped;
  - Esc closes;
  - focus returns to the opener;
  - a closed sheet is `inert`.
- Keyboard-focused work cards scroll into view at full opacity (verified with real Tab events).
- At 400% reflow (320px wide), there is no horizontal scroll, and nothing is clipped except the intentional `sr-only`.
- The viewport allows pinch zoom.
- Form errors are text plus field state, not colour alone:

  | Text | Ratio |
  |---|---|
  | Error, light | 7.14:1 |
  | Error, dark | 12.01:1 |
  | Success, light | 4.83:1 |
  | Success, dark | 10.49:1 |

- The danger border measures 3.22:1 light and 7.81:1 dark.
- All eight category badges pass (5.36–10.81).
- Opacity-0.65 labels pass in both themes (5.10 / 6.85).
- Ink on plates at 0.90 passes (4.55 red / 9.35 yellow).
- Primary hover (paper on oklab-82% red) measures 4.73:1.
- The dark theme's accent passes everywhere it is used (11.58:1).
- The boot loader is `aria-hidden` behind one `role="status"` line, and the app is `inert` until it leaves.
- Arrow-key paging ignores typing targets, IME composition, modifiers, and open dialogs.
- Reduced motion is honoured globally.
